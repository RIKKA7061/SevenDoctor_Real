# SevenDoctors — 개발 메모

유니티 6000.3.22f1 (URP 2D) / 2D 포인트 앤 클릭 추리 어드벤처

---

## 1분 만에 실행하기

1. 유니티에서 프로젝트를 엽니다 (컴파일이 끝날 때까지 기다립니다)
2. 메뉴 **Tools → 일곱 박사 → 게임 씬 만들기**
   (Game 씬 + UI 프리팹이 한 번에 만들어집니다)
3. **Play**

프롤로그(연구실 사고) → 앞마당(나태) → 1층 로비(교만, 도면 = 지도) → 여섯 방 단서 → 파트3~5 → 지하실 엔딩까지
실제로 끝까지 돌아갑니다. 아트가 하나도 없어도 동작합니다.

조작: 화면 속 물건·인물을 직접 클릭 / 대화창 아무 데나 클릭해서 진행 / `Tab` 또는 우상단 버튼으로 증거 노트 /
`M` 또는 우상단 버튼으로 저택 지도 (방 사이 이동은 지도로)

## 이 구조를 택한 이유

### 씬이 4개가 아니라 1개인 이유
방 8개를 각각 씬으로 만들면 방을 옮길 때마다 매니저를 다시 찾아야 하고,
플래그·증거 같은 상태를 씬 사이로 넘기는 코드가 계속 늘어납니다.
`Game.unity` 하나에서 배경과 핫스팟만 교체합니다.

### UI 는 '코드로 만들어서 프리팹으로 굳히는' 방식
UI 계층을 만드는 코드는 `UIRoot.CreateFromCode()` **하나뿐**이고,
**Tools → 일곱 박사 → UI 프리팹 만들기** 가 그걸 에디터에서 한 번 실행해 결과를
`Assets/_Project/Resources/UI/UIRootCanvas.prefab` 으로 저장합니다.

- 프리팹이 있으면 → 런타임이 그걸 꺼내 씁니다. **Hierarchy·Inspector 에서 손으로 고친 값이 그대로 반영됩니다.**
- 프리팹이 없거나 구조가 코드와 안 맞으면 → 코드 생성으로 자동 폴백하고 경고를 남깁니다. 게임은 안 멈춥니다.

씬 파일에는 여전히 카메라와 `GameBootstrap` 둘만 들어 있습니다.
3인이 한 저장소를 쓸 때 가장 심하게 충돌하는 게 씬 파일인데, UI 가 프리팹 하나에 모여 있으면
그 파일을 동시에 건드릴 때만 충돌합니다.

**코드로 UI 구조를 바꿨으면 프리팹을 다시 만드세요.** 안 그러면 폴백이 돌면서 손으로 고친 값이 무시됩니다.

### 구글 시트를 런타임이 아니라 에디터에서 받는 이유
런타임에 시트를 직접 때리면 빌드본이 네트워크에 의존하게 됩니다.
오프라인이면 게임이 안 켜지고, 발표·시연 중 네트워크 사고는 반드시 일어납니다.
대신 기획자가 시트를 고치고 **Tools → 일곱 박사 → 시트 가져오기** 에서 버튼 한 번 누르면 즉시 반영됩니다.
체감은 실시간 연동과 같고, 리스크만 없습니다.

### TextMeshPro 대신 레거시 Text 를 쓰는 이유
TMP 는 한글 폰트 에셋을 따로 굽지 않으면 글자가 아예 안 나옵니다.
지금 단계에서 그 작업을 강제하고 싶지 않아서 OS 폰트(맑은 고딕)를 쓰는 레거시 Text 로 갔습니다.
아트 확정 후 TMP 로 갈아타려면 `UI/UIFactory.cs` 한 파일만 고치면 됩니다.

## 기획자와의 작업 흐름

1. 기획자가 구글 시트를 고칩니다 (탭 11개, 컬럼 정의는 `기획시트_템플릿.xlsx` 참고)
2. 시트 공유를 **'링크가 있는 모든 사용자 - 뷰어'** 로 설정
3. 유니티에서 **Tools → 일곱 박사 → 시트 가져오기** → 스프레드시트 ID 입력 → 가져오기
4. 가져온 직후 **무결성 검사가 자동으로 돌아서**, 깨진 ID 참조를 전부 잡아줍니다

무결성 검사는 이 프로젝트에서 가장 값싼 보험입니다.
`dlg_livin_sloth` 처럼 오타 하나만 나도 게임이 조용히 멈추는데,
그걸 플레이해보고 찾는 것과 콘솔에서 한 줄로 보는 건 디버깅 시간이 열 배 차이 납니다.

**Tools → 일곱 박사 → 데이터 검사** 로 언제든 따로 돌릴 수 있습니다.

## 기획자가 외울 문법 (연출태그)

`Dialogues` 탭 '연출태그' 칸에 씁니다. 여러 개는 그냥 이어 붙입니다. 예) `[sfx:door][fade_out]`

| 태그 | 의미 | 상태 |
|---|---|---|
| `[flag:flg_x]` | 플래그 켜기 | 동작 |
| `[unflag:flg_x]` | 플래그 끄기 | 동작 |
| `[get:ev_x]` | 증거 획득 | 동작 |
| `[goto:dlg_x]` | 다른 대화로 점프 | 동작 |
| `[puzzle:pzl_x]` | 퍼즐 시작 | 동작 |
| `[shake]` | 화면 흔들기 | 동작 |
| `[fade_out]` / `[fade_in]` | 암전 / 복귀 | 동작 |
| `[wait:0.5]` | 대기 | 동작 |
| `[bgm:x]` / `[sfx:x]` | 사운드 | 동작 |
| `[portrait:chr_x:angry]` | 표정 변경 | 동작 |
| `[portrait:chr_x:sad:back]` | 표정 + 몸 방향 (`front` `side_left` `side_right` `back_left` `back_right` `back`) | 동작. `{키}_{방향}.png` 그림이 있는 인물만 (지금은 슬픔 — 그림 없는 인물도 슬픔 그림을 빌려 써서 전원 됨). 없으면 정면 유지 |
| `[ending:end_x]` | 이 줄을 넘기면 엔딩 카드 (Endings 탭 엔딩명) → '처음으로' | 동작. 뒤쪽 줄은 실행 안 됨 |
| `[room:room_x]` | 대사 도중 장면(방) 전환. `[fade_out]` 뒤에 쓰면 눈을 뜨니 다른 곳 | 동작. 그 방의 해금 플래그가 켜져 있어야 함 |

F1 (에디터·개발 빌드) — 대화·퍼즐 미리보기. 진행 중인 대화를 끊고 바로 틀며, 끝나면 플래그·증거를 되돌립니다.

**개발자 방 바로 가기** (에디터·개발 빌드, F1 창이 닫혀 있을 때):

| 키 | 방 |
|---|---|
| `1` `2` `3` | 연구실 · 앞마당 · 1층 로비 |
| `4` `5` `6` | 슬픔의 방 · 나태의 방 · 탐욕의 방 |
| `7` `8` `9` | 분노의 방 · 오만의 방 · 색욕의 방 |
| `PageDown` / `PageUp` | 다음 방 / 이전 방 (교만의 방·식당·정원·복도·지하실은 이걸로) |

번호는 Rooms 시트의 위에서부터 순서입니다 (방을 추가·재배열하면 따라 바뀝니다). 숫자패드도 됩니다.
해금 플래그는 건드리지 않고 잠금 검사만 끕니다 — 진행 상황은 그대로입니다. 한 번 쓰고 나면 지도에서도
잠긴 방을 누를 수 있습니다. 흐르던 대사는 끊깁니다. 시작 화면과 퍼즐 도중에는 안 먹습니다.

## 저택 지도

`M` 또는 상단 '지도' 버튼. 건물 단면도에 방이 층별로 놓이고, 누르면 박사 얼굴 말이 지금 방에서
그 방까지 걸어간 뒤(같은 층은 옆으로, 다른 층은 복도 계단 줄을 타고) 이동합니다.
방 안에는 출구 버튼이 없습니다 — 이동은 전부 지도로 합니다 (앞마당 현관문만 예외).

배치는 `Rooms` 탭의 칸으로 정합니다. 코드 수정 없이 방을 추가·이동할 수 있습니다:

| 칸 | 뜻 |
|---|---|
| `지도층` | `5` ~ `1`, 지하는 `B1`. 비우면 지도에 안 나옴 (연구실) |
| `지도칸` / `지도폭` | 왼쪽부터 몇 번째 칸에서 시작해 몇 칸 차지하는지 |
| `지도연결` | 이 방과 빨간 비밀 통로로 이을 방. **이 방이 열린 뒤에만** 보입니다 (지금은 지하실 ↔ 교만의 방, 지목 뒤) |

잠긴 방(해금조건플래그가 꺼진 방)은 어둡게 '잠김' 으로 나옵니다. 교만에게 도면을 받으면 모든 층이 열리고,
지하실은 교만을 지목한 뒤에 열립니다 (파트4 끝에 교만을 따라 비밀 통로로 내려가 파트5·엔딩).
말 그림은 `Props/prop_token_doctor.png` (`gen_props.py` 가 박사 포트레이트 얼굴로 만듦).
구글 시트에서 가져올 때는 Rooms 탭에 위 네 컬럼이 있어야 합니다.

새로 생긴 방(식당·정원·2~5층 복도·지하실)의 배경은 `python ArtSource/gen_rooms.py` 가 그린 데모입니다.

대화 시스템 자체를 고치는 방법(새 태그 만들기, 칸 추가 등)은 `Docs/대화시스템.md` 에 있습니다.
힌트를 쓰는 법은 `Docs/도우미로봇.md` 를 보세요.

조건 칸(`조건플래그` / `필요플래그`)은 이렇게 씁니다:

```
flg_a              flg_a 가 켜져 있을 때
!flg_a             flg_a 가 꺼져 있을 때
flg_a,flg_b        둘 다 켜져 있을 때 (AND)
flg_a|flg_b        둘 중 하나라도 (OR)
```

## 슬라이딩 퍼즐 (Slide)

그림 한 장을 N×N 으로 잘라 오른쪽 아래 한 칸을 비우고 섞습니다. 빈칸 옆 조각을 누르면 밀려 들어갑니다.
`Puzzles` 탭에 한 줄 쓰면 됩니다:

| 칸 | 값 |
|---|---|
| `타입` | `Slide` |
| `정답` | `그림키` (3×3) 또는 `그림키:칸수` — 예) `pz_invitation:3`, `pz_family:4` |
| `성공플래그` / `성공대화` / `실패대화` | 다른 퍼즐과 같음. `실패대화` 는 '나중에 다시' 를 눌렀을 때 |

그림은 `Resources/Art/Puzzles/{그림키}.png` (없으면 Evidence → Props 에서 찾음). **정사각형**이어야 하고,
**서로 똑같아 보이는 칸이 없어야** 합니다 — 빈 배경뿐인 칸이 둘이면 바뀌어도 눈으로 몰라서 안 끝납니다.
오른쪽 아래 칸은 다 맞춘 순간에만 보이므로 반전을 숨기기 좋습니다.

막혀도 빠져나갈 수 있게 **번호 보기 · 다시 섞기 · 도우미에게 맡기기(40번 움직이면 나타남) · 나중에 다시** 가 붙습니다.
핫스팟에서 부를 때는 `1회성` 을 `FALSE` 로 두세요 — 미뤘다가 다시 눌러야 하니까요 (풀면 `필요플래그` 로 사라지게).

지금 들어 있는 것: 분노의 방 **찢어진 초대장** (`pzl_invitation`). 조각을 맞추면 아이 글씨를 읽고 단서를 얻습니다.
마지막 칸에 "엄마가 끝나고 바로 온다고 약속했음!" 이 있습니다. 그림은 `python ArtSource/gen_puzzles.py`.

## 핫스팟 좌표

`Hotspots` 탭에 `x / y / w / h` 컬럼이 있습니다. **정규화 좌표(0~1), 화면 좌상단 기준**입니다.

- **비워두면**: 화면 하단에 이름표가 보이는 버튼으로 자동 배치됩니다.
  배경 아트가 없어도 기획자가 동선을 바로 확인할 수 있습니다.
- **채우면**: 화면 속 그 자리를 직접 누릅니다. 글자 버튼도, 마우스를 올렸을 때의 이름표·강조도 없습니다.
  누르면 곧바로 이어집니다.

예) 화면 왼쪽 위 1/4 영역 → `x=0, y=0, w=0.5, h=0.5`

### 그 자리에 그림 세우기 — `이미지` 칸

좌표가 있는 핫스팟은 `이미지` 칸으로 물건이나 인물을 방 안에 세워 둘 수 있습니다.
조건(`필요플래그`)이 꺼지거나 1회성으로 소모되면 그림도 같이 사라집니다 — 주운 단서가 방에서 없어집니다.

| `이미지` 칸 | 나오는 것 |
|---|---|
| (비움) | 배경의 그 영역이 클릭 영역. 가운데에 작은 점이 깜빡여서 누를 수 있다는 걸 알려 줍니다 |
| `prop_lever` | `Resources/Art/Props/prop_lever.png` (투명 PNG). 칸 안에 비율을 지켜 맞춰 넣습니다 |
| `chr:chr_sloth` | 그 인물의 포트레이트를 작게 세워 둡니다 (대화창 초상화와 같은 그림) |
| `shadow:chr_sloth` | 같은 그림을 검게 — 아직 정체를 모르는 인물 |

같은 자리에 조건이 다른 핫스팟을 겹쳐 두면 상황에 따라 하는 일이 바뀝니다
(예: 저택 문 — 나태를 만나기 전엔 '살펴보기', 만난 뒤엔 '들어가기').

소품 플레이스홀더는 `python ArtSource/gen_props.py` 가 그립니다. 단서 물건은 노트 그림(`gen_evidence.py`)에서
물건만 떼어 쓰므로 방에서 본 것과 노트 속 그림이 같습니다. 아트가 오면 같은 이름으로 덮어쓰세요.
배경 아트가 바뀌면 좌표도 그 그림에 맞춰 다시 잡아야 합니다 (지금 좌표는 플레이스홀더 배경 기준).
구글 시트에서 가져올 때는 Hotspots 탭에 `이미지` 컬럼이 있어야 합니다.

## 아트

**지금 플레이스홀더 아트가 들어가 있습니다.** 실제 아트가 나오면 같은 경로·같은 파일명으로
덮어쓰기만 하면 코드는 한 줄도 안 고쳐도 됩니다.

```
Resources/Art/
├── Backgrounds/{배경키}.png    1920×1080   ← Rooms 탭 '배경키'와 파일명 일치
├── Characters/{포트레이트키}.png  700×1200   ← Characters 탭 '포트레이트키'와 일치 (몸)
├── Faces/{표정}.png            700×1200   ← Dialogues 탭 '표정'과 일치 (표정만, 투명 배경)
└── Evidence/{아이콘키}.png       512×512    ← Evidence 탭 '아이콘키'와 일치
```

**PNG 를 폴더에 넣기만 하면 됩니다.** Texture Type 을 Sprite 로 바꾸는 작업은
`ArtImportSettings.cs` 가 자동으로 해줍니다. (한 번만 깜빡해도 "왜 배경이 안 나오지"로
한참 헤매게 되는 사고라, 아예 막아놨습니다)

### 몸과 표정을 나눈 이유

일곱 박사가 전부 같은 얼굴이라는 게 설정이므로, **표정 한 세트를 전원이 공유**합니다.
7인 × 5표정 = 35장이 아니라, 몸 8장 + 표정 5장 = 13장이면 끝납니다.
아트 담당 작업량이 1/3 이하로 줄어듭니다.

- 몸: 인물마다 옷깃 강조색 + 소품 하나로 구별 (교만만 얼굴이 어둠에 묻힌 버전)
- 표정: `normal / surprised / angry / sad / sleepy` — 몸과 같은 캔버스 크기, 얼굴 부분만 그리고 나머지는 투명

새 표정을 추가하려면 같은 규격으로 PNG 를 넣고 시트 '표정' 칸에 그 이름을 쓰면 됩니다. 코드 수정 불필요.

### 손그림 포트레이트 (새 그림체)

얼굴까지 다 그려진 그림은 `Resources/Art/Portraits/` 에 둡니다. 이 폴더에 `{포트레이트키}.png` 가
있으면 `Characters` 보다 먼저 쓰고, **공용 표정을 겹치지 않습니다** (얼굴이 둘이 되니까).
그래서 지금은 표정 칸을 바꿔도 그림이 안 바뀝니다 — 표정마다 따로 그려야 합니다.

**그림이 있는 인물과 없는 인물**

| 인물 | 포트레이트키 | 지금 그림 |
|---|---|---|
| 슬픔 | `sorrow` | 자기 그림 — 정면 + 옆 보기·돌아보기(좌우) + 입 |
| 분노 / 오만 / 탐욕 / 색욕 | `wrath` / `arrogance` / `greed` / `lust` | 자기 그림 — 정면 + 입 |
| 박사 / 나태 / 교만(딸) | `doctor` / `sloth` / `pride` | **임시** — 슬픔 그림의 머리·옷 색만 바꾼 것 (방향·입 포함) |

임시 그림은 `python ArtSource/make_standins.py` 가 만듭니다 (박사 갈색 머리·흰 가운, 나태 초록, 교만 검은 머리·보라 옷).
진짜 그림이 오면 같은 이름으로 덮어쓰면 됩니다. 그 파일마저 없는 인물은 `sorrow.png` 를 빌려 씁니다
(`PortraitView.FallbackPaintedKey`, 빈 문자열이면 빌려 쓰기를 끔).

방향 그림은 `{키}_{방향}.png` (`sorrow_side_left`, `sorrow_back_left` …). 없는 방향은 가장 비슷한 방향으로
대신합니다 (예: `back` 이 없으면 `back_left` → `side_left` → 정면). 방향 그림이 하나도 없는 인물은 늘 정면입니다.

**캐릭터 시트에서 뽑기** — `ArtSource/sheets/{키}_sheet.webp` (왼쪽에 전신 정면, 오른쪽에 머리 세 각도):

```
python ArtSource/make_portraits.py          # 전부 (또는 뒤에 키를 적어 골라서: wrath lust)
python ArtSource/paint_mouths.py            # 벌린 입
python ArtSource/make_standins.py           # 그림 없는 인물의 임시 그림 (슬픔을 다시 뽑았을 때)
python ArtSource/gen_evidence.py            # 노트의 인물 카드
python ArtSource/gen_props.py               # 지도의 박사 말 (박사 그림이 바뀌었을 때)
```

새 인물은 시트를 `sheets` 에 넣고 `make_portraits.py` 의 `CHARACTERS` 에 한 줄(몸 위의 한 점)을 더한 뒤,
`paint_mouths.py` 의 `MOUTHS` 와 `gen_evidence.py` 의 `FACE_BOXES` 에 입·얼굴 자리를 적습니다.
팔과 몸 사이처럼 외곽선에 갇힌 흰 배경이 남으면 `holes` 에 그 안의 한 점을 적어 주세요 (색욕이 그 예).

시트에 전신은 정면 하나뿐이라 방향 그림은 몸을 그대로 두고 머리만 갈아 끼워 만듭니다 —
`side_*` 는 3/4 얼굴, `back_*` 는 옆얼굴. `CHARACTERS` 에 `heads` 를 적은 인물만 만들고, 지금은 슬픔뿐입니다
(그림 없는 인물이 슬픔을 빌려 쓰므로 연출에 쓰이는 방향은 전부 여기서 나옵니다). 뒷모습은 시트에 없습니다.

한 장에 여러 방향 전신이 나란히 그려진 턴어라운드 시트는 잘라 주는 도구가 있습니다. 배경 지우기·정렬·좌우반전까지 합니다.

```
python ArtSource/cut_turnaround.py ArtSource/sheets/wrath_turnaround.png wrath
python ArtSource/cut_turnaround.py 시트.png 키 front,side_left,back_left,back
```

방향 이름은 시트 왼쪽부터 순서대로입니다. `_left` 로 끝나는 방향은 `_right` 가 자동으로 생깁니다.
배경은 종이처럼 밝은 무채색이어야 하고, 인물 외곽선은 검은 선이어야 합니다.

**말할 때 입 움직이기** — `{그림}_mouth.png` (그림과 같은 캔버스, 벌린 입만 불투명) 를 두면 대사가
찍히는 동안 켰다 껐다 합니다. 다문 입은 원래 그림 것을 씁니다. 없는 방향은 입이 안 움직입니다.
`python ArtSource/paint_mouths.py` 가 입 위치(파일 안 `MOUTHS`)에 벌린 입을 그려 줍니다.
손으로 그린 입을 쓰고 싶으면 같은 규격 PNG 로 덮어쓰면 됩니다.

### 증거 그림 (노트에서 크게 보기)

`Resources/Art/Evidence/{아이콘키}.png` — Evidence 탭 '아이콘키' 와 이름이 같으면 붙습니다.
노트 오른쪽에 크게 나오고, 누르면 화면 가득 확대됩니다 (휠·클릭으로 더 확대, 드래그로 이동).
추리 퍼즐 카드에도 그림과 `+` 버튼이 붙어서 퍼즐 중에도 들여다볼 수 있습니다.

**작은 단서는 설명에 쓰지 말고 그림 안에만 넣습니다.** 확대해서 찾아내는 게 추리가 되게 하려는 것입니다.
지금 그림에 숨어 있는 것:

| 증거 | 확대하면 보이는 것 |
|---|---|
| 저택 도면 | 방마다 빨간 X '동력부', 구석 연필 메모 '3:12' 와 바를 정 7획 |
| 찢어진 초대장 | 맨 아래 '엄마가 끝나고 바로 온다고 약속했음!' |
| 다 녹아버린 초 6개 | 꽂는 자리는 7개, 한 자리가 비어 있음 |
| 트로피 모형 | 명판 '평행세계 이론 최고상 · 6. 14.' |
| 선물상자 | 카드 '6.14 생일 축하해 — 엄마가' |
| 손목시계 | 3:12, 날짜창 '14' |
| 캘린더 | 14일 칸에 아이 글씨 '내 생일!!' 과 어른 글씨 '시상식' |

플레이스홀더는 `python ArtSource/gen_evidence.py` 가 그립니다 (1024px). 인물 카드(`ic_chr_*`)는
포트레이트에서 얼굴을 잘라 만들어서, 인물 그림이 들어오면 다시 돌려야 합니다.
아트 담당 그림이 오면 같은 이름으로 덮어쓰면 됩니다 — 위 표의 디테일은 꼭 살려 달라고 전하세요.

### 플레이스홀더를 다시 뽑고 싶으면

`ArtSource/gen_art.py` (파이썬 + Pillow). 색·비율·구도가 전부 숫자로 되어 있어서
값만 바꿔 다시 돌리면 됩니다.

```
python ArtSource/gen_art.py
```

Live2D 는 이번엔 제외합니다. 표정 교체만으로도 충분히 살아 움직입니다.
