# 대화 시스템 고치는 법

두 층으로 나뉩니다. **어느 층을 건드려야 하는지 먼저 정하는 것이 이 문서의 목적입니다.**

| 하고 싶은 일 | 건드릴 곳 | 코드 수정 |
|---|---|---|
| 대사 추가·수정, 분기, 표정·연출 붙이기 | 구글 시트 (`Dialogues` / `Choices`) | 없음 |
| 새 연출 태그 만들기 (`[zoom:2]` 같은 것) | `DialogueRunner.cs` | 한 줄 |
| 대사 줄에 새 칸 추가 (예: '음성파일') | `Tables.cs` + 시트 | 두 군데 |
| 출력 방식 자체 변경 (타이핑 속도, 창 모양) | `DialogueView.cs` / `DialogueRunner.ShowLine` | 여기만 |

대부분의 기획 작업은 **첫 줄**입니다. 코드를 열 일이 없습니다.

---

## 1. 데이터만 고치는 경우

`Dialogues` 탭의 칸 구성:

```
dialogue_id, line_no, speaker_id, 표정, 대사, 대사_en, 연출태그, 조건플래그, 다음대화, 비고
```

- `dialogue_id` 가 같은 줄들이 `line_no` 순서로 한 덩어리가 됩니다.
- 덩어리의 **마지막 줄**에 있는 `다음대화` 가 다음 덩어리를 정합니다. 중간 줄의 `다음대화` 는 무시됩니다 — 중간에서 갈라지고 싶으면 `[goto:dlg_x]` 태그를 쓰세요.
- `speaker_id` 를 비우면 지문 취급입니다. 포트레이트가 숨겨지고 말소리도 나지 않습니다.
- `조건플래그` 가 맞지 않는 줄은 **통째로 건너뜁니다.** 같은 대화 안에서 '증거를 이미 얻었으면 다른 대사' 같은 걸 이걸로 만듭니다.

선택지는 `Choices` 탭에서 `dialogue_id` + `line_no` 로 대사 줄에 붙습니다. 그 줄이 출력된 **직후**에 뜹니다.

태그 문법과 플래그 조건 문법은 `README_개발.md` 의 「기획자가 외울 문법」 절에 있습니다.

---

## 2. 새 연출 태그를 만드는 경우

태그는 세 갈래로 나뉘어 처리됩니다. **어느 갈래에 넣느냐가 실행 시점을 정합니다.**

| 갈래 | 함수 | 시점 |
|---|---|---|
| 연출 | `ProcessPresentationTags` | 글자가 찍히기 **전** |
| 상태 | `ProcessStateTags` | 글자가 다 찍히고 **클릭한 뒤** |
| 흐름 | `PlayCore` 안의 5번 블록 | 선택지까지 끝난 **맨 마지막** |

예를 들어 `[zoom:2]` 를 만든다면 연출 갈래입니다. `DialogueRunner.cs` 의 `ProcessPresentationTags` switch 에 한 칸 추가하면 끝입니다:

```csharp
case "zoom":
    if (float.TryParse(tag.Value, out var scale))
        yield return Game.UI.Zoom(scale);
    break;
```

인자는 `[key:a:b]` 까지 받습니다 (`tag.Value`, `tag.Value2`). 세 개 이상이 필요하면 `TagUtil.Tag` 를 배열로 바꿔야 하는데, 거기까지 간 태그는 대체로 설계가 잘못된 것입니다 — 새 시트 탭을 파는 편이 낫습니다.

**주의:** 태그를 새로 만들면 `README_개발.md` 의 표에도 한 줄 넣으세요. 표에 없는 태그는 기획자가 쓸 수 없습니다.

---

## 3. 대사 줄에 새 칸을 추가하는 경우

예를 들어 '음성파일' 칸을 붙인다면:

1. 구글 시트 `Dialogues` 탭에 `음성파일` 칸 추가
2. `Tables.cs` 의 `DialogueRow` 에 필드 + 파싱 한 줄
   ```csharp
   public string VoiceClip;
   ...
   VoiceClip = CsvParser.Str(r, "음성파일"),
   ```
3. Unity 에서 `Tools > 일곱 박사 > 시트 가져오기` 로 CSV 다시 받기

**번역이 필요한 칸이면** `_en` 칸을 같이 만들고 `Ko`/`En` 필드 쌍 + 프로퍼티로 쓰세요. 기존 칸들이 전부 이 모양입니다:

```csharp
public string TextKo, TextEn;
public string Text => Loc.Pick(TextKo, TextEn);
```

프로퍼티 이름을 원래 이름으로 두면 부르는 쪽은 한 줄도 안 고쳐도 됩니다.

## 4. 출력 방식을 바꾸는 경우

- **타이핑 속도** — `GameBootstrap.CharInterval` (인스펙터). 코드 수정 불필요.
- **넘기는 키** — `DialogueRunner.WasAdvanceKeyPressed`. 노트·퍼즐·선택지가 떠 있을 때 빠지는 가드는 `Update` 에 있습니다. 새 UI 를 덮어 띄우면 **그 가드에도 한 줄 넣어야 합니다** — 안 그러면 뒤에서 대사가 같이 넘어갑니다.
- **말소리** — `ShouldVoice` 가 어느 글자에서 소리를 낼지 정합니다. 목소리 자체는 `AudioSynth.VoiceBlip`.
- **창 모양·글자 색** — `DialogueView.cs`. UI 는 코드로 만들어 프리팹으로 굳히는 구조라, 여기를 고치고 프리팹을 다시 구워야 합니다.

---

## 5. 다른 코루틴 안에서 대사를 틀고 싶을 때

`Play()` 는 게임 상태(`IsPlaying` / `GameState`)를 잡습니다. 이미 대화 중이면 무시됩니다.

퍼즐 안에서 오답 반응을 틀 때처럼 **겹쳐 불러야 하면** `PlayCore` 를 직접 `yield return` 하세요. 상태를 건드리지 않습니다.

```csharp
yield return Game.Dialogue.PlayCore("dlg_wrong_answer");
```

---

## 고장 났을 때 보는 곳

| 증상 | 원인 |
|---|---|
| `'dlg_x' 대화를 찾을 수 없습니다` | 시트 오타, 또는 CSV 를 다시 안 받음 |
| `512회 이상 연쇄됐습니다` | `다음대화` / `[goto]` 가 고리를 만듦 |
| 대사가 통째로 안 나옴 | `조건플래그` 가 안 맞아 모든 줄이 걸러짐 |
| 선택지가 안 뜸 | `Choices` 의 `line_no` 가 실제 대사 줄과 어긋남 |
| 말소리는 나는데 입이 안 움직임 | `speaker_id` 가 비어 있음 (지문 취급) |
